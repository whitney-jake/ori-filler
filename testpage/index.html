Form Filler Test Page

This page is the manual verification fixture for the Form Filler extension. Load the extension unpacked, open this page over http://localhost:8000/testpage/index.html, and click the Fill button. Do not open this page with a file:// URL. Content scripts do not run on file:// URLs.

1. Customer Form

Profile: create-customer.json. The first five fields fill here.

Last name starts pre-filled with "Doe". The profile field for it has skipIfFilled: true, so the fill skips it and "Doe" stays.

Tier (radio group, selected by value)

2. Scenario Form

Profiles: create-customer.json and login.json reference this form for the scenario fields.

2a. Ambiguous field (picker)

Two inputs share the name city. One profile field points at .//input[@name='city'], which matches both. The fill shows the picker. Pick either city to continue.

2b. Optional unresolved field

The profile field points at .//input[@name='missingOptional'], which does not exist. The field has optional: true. The fill skips it and continues.

2c. Required failure (not found)

The profile field points at .//input[@name='missingRequired'], which does not exist. The field is required by default. The fill stops and reports the failure.

2d. Required failure (disabled input)

The profile field points at the disabled input name="locked". The element resolves but the fill cannot write to it. The fill stops, reports the failure, and outlines the element.

3. Login Form

Profile: login.json.

The login profile fills the username, password, remember checkbox, and the role radio group (selected by label). Then it hits the disabled input in the scenario form, which stops the fill.

Role (radio group, selected by label)
